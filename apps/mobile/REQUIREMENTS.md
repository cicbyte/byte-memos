# byte-memos 移动端 · 需求文档（PRD）

> 状态：草案 v0.1（待评审）
> 日期：2026-10-13
> 仓库位置：`apps/mobile/`（Flutter，Android 优先）
> 上游依赖：byte-memos 桌面端「REST API 服务」（已具备，`/api/v1`）

---

## 1. 背景与目标

byte-memos 目前只有桌面端（Tauri）和浏览器剪藏扩展。备忘录的核心场景是**随时记、随手查**——恰恰发生在离开电脑的时刻：通勤路上想到一个点子、手机上看到一段内容想存、睡前回顾今天的记录。

移动端要解决三件事：

1. **速记**：10 秒内完成「打开 app → 记下 → 收起」
2. **查看与检索**：手机上流畅浏览/搜索全部备忘录
3. **收纳**：承接系统分享（文字/链接/图片），把手机上的内容一键收进 byte-memos

**非目标（本期不做）**：

- 不做独立数据库/单机模式——移动端是桌面端的远程视图与入口，数据只有一份，在桌面端
- 不做 iOS 上架（技术选型保持跨平台可行，但交付与测试只覆盖 Android）
- 不做 P2P/公网穿透（局域网直连够用；外网访问列为远期）

## 2. 产品原则

| # | 原则 | 说明 |
| --- | --- | --- |
| 1 | **数据只有一份** | 移动端不落主数据；一切写操作直达桌面端 REST，失败即提示，不静默本地暂存主数据 |
| 2 | **玻璃为容器，不为内容让路** | 液态玻璃只用于导航、浮层、工具条等「容器」；正文文字永远在高对比实体层上，可读性优先 |
| 3 | **离线宽容** | 断网时可浏览最近缓存（只读），明确标注「离线内容，X 分钟前同步」；写操作失败给重试 |
| 4 | **桌面端永远知情** | 移动端产生的数据（速记、分享收纳）带来源标记，在桌面端可辨识 |

## 3. 用户与核心场景

单一用户画像：**byte-memos 桌面端的重度用户本人**（个人知识库，非团队）。

| 场景 | 描述 | 频次 |
| --- | --- | --- |
| S1 速记 | 地铁上想到点子，掏手机 → app → 记一句 → 锁屏 | 高，每日多次 |
| S2 分享收纳 | 微信/浏览器里看到好内容 → 系统分享 → byte-memos → 自动带来源 | 高 |
| S3 回顾 | 睡前躺床上翻今天的记录、看统计 | 中 |
| S4 检索 | 和朋友聊天时想引用某条备忘 → 搜索 → 找到 → 原文分享出去 | 中 |
| S5 管理 | 清理误存、置顶常用、管理标签 | 低 |

## 4. 总体架构与技术选型

### 4.1 技术栈

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 框架 | **Flutter（Android 优先）** | 团队已有 dsh-mobile 成熟范式（连接层/配对/安全存储/抽屉外壳可直接参考）；BackdropFilter 玻璃渲染能力完备；MuMu 模拟器 x86_64 支持好 |
| 状态管理 | Riverpod | 连接状态/列表分页/筛选的组合复杂度适中，Riverpod 测试友好 |
| 网络 | dio + retrofit 风格生成 | 拦截器统一注入 `X-API-Key`、超时与错误映射 |
| 安全存储 | flutter_secure_storage | API Key 进 Android Keystore，绝不进 SharedPreferences 明文 |
| 本地缓存 | shared_preferences（轻量配置）+ sqflite（只读快照缓存，P1） | 见原则 3 |
| Markdown 渲染 | flutter_markdown_plus（dsh-mobile 同款） | GFM 支持 + 代码高亮 + 暗色定制，已被 dsh-mobile 验证 |

### 4.2 连接模型（沿用 dsh-mobile 成熟模式）

```
┌─────────────┐  Wi-Fi / adb reverse   ┌──────────────────────┐
│  Flutter App │ ────── HTTP JSON ────▶ │ 桌面端 REST API      │
│             │   X-API-Key 头          │ http://ip:8318/api/v1│
└─────────────┘                         └──────────────────────┘
```

- **连接层三件套**（对应 dsh-mobile `lib/dsh/` 的分层）：
  - `transport`：纯 HTTP 传输，可替换（为远期 relay 留缝）
  - `client`：REST 端点封装（memos/categories/tags/stats/trash）
  - `conn_store`：连接配置持久化（多套配置、激活切换、连通性探测）
- **配对方式**（优先级从高到低）：
  1. **扫码配对**（P1，需桌面端小改）：桌面端「REST API 服务」页显示二维码（`http://ip:port/api/v1#key`），手机扫码一次完成配置——dsh-mobile `qr_payload` 同款
  2. **手动配置**（P0）：填 IP:端口 + API Key，一键测试连接
  3. adb reverse 联调：`adb reverse tcp:8318 tcp:8318` 后用 `127.0.0.1:8318`（开发期专用，README 写明）

### 4.3 页面信息架构（底部玻璃导航 + 中央玻璃 FAB）

```
┌────────────────────────────────┐
│  内容层（实体背景，高对比正文）      │
│                                │
│      ◉ 玻璃 FAB（新建/速记）      │
│                                │
│ ┌──────────────────────────┐   │
│ │ 玻璃底栏：流 · 搜索 · 统计 · 我的│ ◀ 液态玻璃容器
│ └──────────────────────────┘   │
└────────────────────────────────┘
```

| Tab | 内容 |
| --- | --- |
| 流 | 备忘录时间线（卡片流，置顶分组 + 按天分组），无限滚动 + 下拉刷新 |
| 搜索 | 全文搜索 + 标签/分类筛选（复用 `GET /search/memos`、`/memos?tag=&category=`） |
| 统计 | 总量/今日新增/连续天数/标签云（`GET /stats`、`/tags`） |
| 我的 | 连接管理（状态、切换、测试）、外观（玻璃强度/跟随系统深色）、关于 |

浮层（玻璃材质）：新建/编辑页（底部弹层 modal bottom sheet）、详情页、图片查看器、删除确认、Toast。

## 5. 液态玻璃设计规范（核心差异点）

> 参考 Apple Liquid Glass（2025）语言，跨平台自定义实现。原则：**玻璃是层级语言，不是装饰**——用透明度层级替代阴影层级表达「浮在内容之上」。

### 5.1 材质令牌（Design Tokens）

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `glass.ultraThin` | blur 8px · 白 8% 不透明度 · 饱和度 120% | 静态浮层背景（分组头、卡片容器） |
| `glass.regular` | blur 20px · 白 12% · 饱和度 140% | 底部导航栏、FAB |
| `glass.thick` | blur 32px · 白 18% · 饱和度 160% | 模态弹层（新建/编辑/详情） |
| `glass.border` | 1px 渐变描边（上白 35% → 下白 8%） | 所有玻璃容器边缘高光 |
| `glass.specular` | 顶部内阴影 2px 白 25% | 模拟光源在上 |

暗色模式：白色叠加换黑色叠加（黑 6%/10%/16%），描边换白 12%→3%，blur 值不变。

### 5.2 折射与动效

- **边缘折射**：玻璃容器圆角处 1.5px 内描边亮线（模拟光线弯折），列表滚动时高光随滚动方向轻微偏移（`ShaderMask` 实现，性能预算内）
- **触觉反馈动效**：FAB 按下 `scale 0.96` 弹性回弹（spring 仿真），玻璃底栏点击图标时图标在玻璃内「悬浮位移」8px
- **流体过渡**：新建弹层从 FAB 位置展开（Hero + 圆角插值），详情页推入时玻璃卡片先「液化」放大再固化
- 所有动效 300ms 内完成，`reduce motion` 系统设置下退化为 opacity 渐变

### 5.3 性能预算与降级（玻璃是大头，必须立规矩）

| 档位 | 判定 | 表现 |
| --- | --- | --- |
| 全效果 | GPU 合成 blur ≥ 60fps（MuMu / 近年真机） | 完整令牌 + 折射动效 |
| 简化 | 中端机 / 帧率波动 | blur 减半、去折射动效，保留透明度层级 |
| 兜底 | `BackdropFilter` 不可用或低端 | 纯色半透明（12% 白/黑）+ 描边，视觉语言不丢 |

- 每屏同时存在的 `BackdropFilter` **≤ 2 个**（底栏 + 一个浮层）；列表卡片一律用预渲染的伪玻璃（`ImageFilter` 只算一次）或纯透明度
- 用户可在「我的 → 外观」手动切换 玻璃强度：自动/全开/省电

## 6. 功能需求

> 验收标准（AC）逐条可测。P0 = 首个可用版本（MVP）。

### 6.1 P0（MVP，里程碑 M1）

| ID | 功能 | 说明 | 验收标准 |
| --- | --- | --- | --- |
| F01 | 连接配置 | 手动填 `http://ip:port/api/v1` + API Key；测试连接按钮区分「通/Key 错/连不上」三种反馈 | 三种状态文案与图标正确；配置重启保留 |
| F02 | 备忘录流 | 时间线卡片：标题/正文摘要（Markdown 源文截断 6 行）/标签 chip/时间；置顶组在前；按天分组头 | 首屏 ≤ 1.5s 出内容（局域网）；滚动 1000 条不掉帧（60fps 目标） |
| F03 | 新建/编辑 | 底部玻璃弹层；纯文本输入 + Markdown 预览切换 + 常用格式快捷条（标题/列表/加粗/代码/引用）；标题、分类、标签输入 | 10 秒内完成一条速记（S1 场景实测）；保存后流内即时可见 |
| F04 | 删除 | 删除走确认弹层；删除后 Toast 可撤回（调恢复接口） | 回收站可见被删项；撤回成功列表复原 |
| F05 | 搜索 | 输入即搜（防抖 300ms）+ 标签/分类筛选 chips | 高亮命中词；空结果有引导 |
| F06 | 分享收纳 | 注册系统分享目标（text/plain）：分享文字 → 预填新建弹层，自动附来源 app 名 | 微信/浏览器分享进来内容完整、来源标注正确 |
| F07 | 离线宽容 | 断网时展示最近一次成功响应的只读快照 | 顶部明确「离线 · X 分钟前」横幅；写操作提示失败可重试 |

## 7. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 安全 | API Key 仅存 Keystore；HTTP 明文仅限局域网并在连接页明示风险；不内置任何 telemetry |
| 性能 | 冷启动 ≤ 2s（MuMu 实测）；列表滚动 60fps；交互响应 < 100ms |
| 兼容 | Android 8.0+（minSdk 26）；MuMu 模拟器 12（Android 12 x86_64）为一级测试环境 |
| 无障碍 | 正文对比度 ≥ 4.5:1（玻璃容器上的文字用实体垫底保证）；支持系统字体缩放 |
| 国际化 | 中/英文案表，默认跟随系统 |

```powershell

adb connect 127.0.0.1:16384
flutter run                          # 或 --dart-define=SERVER_URL=http://127.0.0.1:8318/api/v1
adb reverse tcp:8318 tcp:8318        # 模拟器内用 127.0.0.1 直达宿主机桌面端
```

| 层 | 手段 |
| --- | --- |
| 单元 | client 端点封装契约测试（桌面 REST 真跑 + 录制回放） |

## 10. 风险与对策

| 风险 | 等级 | 对策 |
| --- | --- | --- |
| 玻璃渲染性能不达标（模拟器 GPU 差异大） | 高 | §5.3 三档降级 + 每屏 BackdropFilter ≤2 硬约束；MuMu 即一级环境从 M1 就盯 |
| 桌面端服务没开 → 移动端「失联」体验差 | 高 | F01/F07 状态可视化；连接失败引导「去桌面端开 REST 服务」的图文 |
| REST 能力缺口（附件/AI）拖 P1/P2 | 中 | D1–D3 清单先行立项，移动端按依赖排期不被卡死 |
| HTTP 明文传输被质疑 | 中 | 文档明示局域网信任模型；远期可选 HTTPS 自签 |

## 附：术语

- **玻璃容器**：带 BackdropFilter 模糊 + 透明度 + 描边高光的 UI 容器组件（`GlassContainer` widget，三档令牌）
- **配对**：手机获得桌面端地址与 Key 的过程（手动或扫码）
- **离线快照**：最近一次成功响应的只读缓存数据
